# 跨轮目标

> 更新日期：2026-10-16

在 REPL、Full TUI、Inline TUI 或 Web 工作台创建目标，会先形成草案并等待确认：

```text
/goal 修复解析器并提供通过测试的证据
/goal refine 保留现有公开 API，补充边界条件测试
/goal confirm goal-ID REVISION
```

模型先只读探索，将原始请求整理为子目标、可观察验收项和证据要求。通常一至两轮讨论即可确认；不按轮数自动确认。检查展示的原始请求、范围、约束和验收项，使用提示给出的确切 ID 与 revision 确认。草案尚未有效形成时继续澄清，不能确认。Web 的目标面板提供相同的修改草案和确认版本操作。

新目标默认独立智能体审核，20 个执行轮次、60 分钟从确认启动时计算；讨论不消耗执行轮数，模型调用仍计费。执行者每轮自然结束后，宿主启动继承上下文的只读审核者，先读本轮结论：明确还有契约内下一步时可轻量返回；声称完成、结论不明或矛盾时检查文件与产物。审核者自然返回描述性报告。宿主 agent 根据报告调用 GoalReview 提交继续、完成或外部阻断结论，工具拒绝时会返回具体原因供宿主纠正重试。全部完成才进入完成或后续检查器/人工门槛；还有工作或缺证据时继续执行。一次验收编排（独立审核、宿主提交、重新审核和检查器）最多 10 分钟，仍受 Goal 绝对期限和 Token 预算约束。独立代理无法返回时显示审核待重试（目标条与详情都可重试）；报告已返回但宿主未提交时显示“宿主结论提交未完成”，可“重试提交”并复用有效报告。两者都不重新执行任务。同一外部阻断须有实际读取的事实证据，默认连续三个执行轮才停止。审核者不能调用结论提交工具或修改目标；显式配置主代理工具白名单时须包含 GoalReview。

`/goal human <请求>` 增加人工验收门槛；审核通过后 `/goal approve <核对说明>` 提交人工完成依据。`MINK_GOAL_CHECK` 配置固定检查命令，例如 `cargo test -p my-crate`，配置的检查器也必须通过；它改变审核证据后会在同一执行轮内重新只读审核，最后一轮也可完成。人工批准仍受原截止时间约束；`/goal verified <请求>` 显式选择检查器验收。审核者自己不能执行命令或修复文件，缺少测试证据会交执行者补充。

```text
/goal pause
/goal budget 30 90 200000
/goal resume
/goal cancel
/goal clear
```

预算的轮数是总额度；分钟数从调整时计算新截止，省略 Token 软限额则移除。调整不自动恢复。暂停不重置时间，离线时间也计入已确认目标的期限。草案不能用 resume 绕过确认；改变已确认契约需取消再创建。

执行失败后显示 failed，停止自动执行；排除故障后可点击“重试目标”或 `/goal resume` 重试原目标，不必新建契约。从已提交历史开始下一执行轮，已提交工具调用不会重放，已用额度和原期限保留。若已过期、轮数耗尽或 Token 软限额用尽，先在目标详情填写总轮数上限、从现在起允许的分钟数并“调整预算”，再明确重试；未填写项及 Token 软限额保持不变，调整不会自动执行。未知副作用须先对账，当前 runtime 的故障闩锁须先关闭并重开会话处理。这与“重试审核/重试提交”复核同一轮不同；审核中的恢复不额外消耗执行轮。completed/cancelled 不可恢复。

运行中补充要求沿用当前执行 turn 的引导入口；目标持有执行和验收所有权时独立任务返回 busy，先暂停再提交。Ctrl+C 暂停已确认目标；正常退出保留 active 意图。Rust/server 需显式接起恢复目标，终端在 UI 接入后接起已确认 active；paused/blocked/budget_exhausted 不自动恢复。

`/goal` 之后只有列出的子命令有特殊含义，其余文本一律视为目标正文：`/goal 修复解析器` 是创建。参数首词与某个子命令只差一处拼写（含相邻换位，如 `cancal`、`confrim g12`、`refne`）会被拒绝并提示正确的子命令，不会把自己写成目标正文；首词不接近任何子命令的多词句子仍是正文，例如 `/goal fix the cancal bug`。

`/goal human 目标正文` 创建人工验收目标；独立审核满足目标契约和配置的检查器后，目标进入人工验收，以 `/goal approve 核对说明` 确认。默认 `/goal approve` 使用明确的终端确认说明。`/goal verified 目标正文` 使用 `MINK_GOAL_CHECK` 配置的检查命令，例如先设置 `MINK_GOAL_CHECK='cargo test -p my-crate'` 再启动。命令固定在 runtime 配置，具有 60 秒检查超时，经现有 Bash surface、审批、取消和输出保护执行；改变配置身份后原目标不会降级为模型判断。未配置 `MINK_GOAL_CHECK` 的部署中，工作台命令面板把 `/goal verified` 标为不可用，而不是提出必然被服务端拒绝的请求。

未决副作用需先检查文件或远端实际结果，用 `/goal reconcile <调查证据>` 记录对账，再确认或恢复；不会合成成功结果。

/goals 或点击状态标记查看契约、预算、审核结论和证据。完成依据区分 agent_reviewed、verified、human_approved；旧已结束目标仍展示原 model_reported。执行者结束本轮不表示 Goal 完成。clear 只隐藏已结束目标，历史保留。

完整接口、状态和恢复约束见 [Goal 契约](../reference/goals.md)。

界面将审核分为“判断是否需要验收”“检查完成证据”“宿主提交结论”。“本轮部分完成，继续执行”只表示调度继续，不证明验收项通过；详情分别显示剩余要求、下一步、分流报告及历史完整审核所属轮次。连续三轮仍指向相同剩余要求时自动检查证据，反馈换一种措辞不会重置计数。最后一轮仍未完成则保存反馈并停于额度耗尽。
