### 五轮审核采纳清单（范围收缩）

1. **删除共享 index.jsonl**：缓存只保存以原始字节 SHA-256 命名的不可变对象；来源路径仅写入当前工具结果，不做跨 session 索引；
2. **删除所有图片转换**：归一化、EXIF 旋转、色深转换、缩放、重编码、variant cache、`request-images/` 全部**延期二期**；
3. **严格限制 MIME**：magic sniff 所得 MIME 必须同时属于 Mink 支持集合与模型 `allowed_mime`，否则 `UNSUPPORTED_IMAGE_MIME`；
4. **不做完整解码**：一期 = 有界读取 + 图片头尺寸探测；保留原始字节上限、单边上限、总像素上限（checked_mul）、图片数量/原始字节配额、最终 HTTP body 检查；删除 `max_alloc` 与解码并发内存限制；
5. **数据定义**："归一化字节"→"原始图片字节"；图片 ID = 原始字节 SHA-256；请求时直接 base64 原始字节；
6. **完整性承诺**：文件头或尺寸无法解析时拒绝；一期不保证发现深层编码损坏（provider 可能请求时返回错误）。

**API 核实**：image 0.25 `ImageReader::into_dimensions()`（image_reader_type.rs:302，头部探测不解码）、`limits()`（:137）、`with_guessed_format()`（:254）——一期只用到这三个。

## 1. 目标与边界

**目标**：让 agent 像读文本一样自由读图——对支持视觉输入的模型，`Read` 图片路径（或 `image://` 引用）后图片以 OpenAI 标准 `image_url` part 注入下一次 LLM 请求。协议统一：Read 是唯一读取入口，`image://` 是图片引用 scheme。

**前置条件（能力冻结）**：视觉能力在 session 初始化时解析并冻结（§3）。能力不支持时**行为与现状逐字节一致**（含 `image://` 未知 scheme fail-closed 现状）。

**非目标（本期明确不做）**：

- 人工输入附件（CLI/TUI 传图）
- 图片生成、图片编辑输出
- 非白名单格式（HEIC、SVG、BMP 等）——fail closed
- 同一 session 内切换到能力指纹不同的模型（需要不同协议/限额 → 新建 session）
- DeepSeek Files API `file_id` 上传路径（二期）
- **图片转换（二期）**：归一化、EXIF 旋转、色深转换、缩放、重编码、variant cache
- **完整解码校验（二期）**：一期只做头部探测，深层编码损坏由 provider 兜底
- home 缓存清理策略（二期）

**协议前提**：多模态图片只能是 user-role content 的 part；工具结果在 OpenAI 协议中是 tool-role 字符串消息。图片由 runtime 注入，工具只负责"捕获"。

## 2. 总体数据流

```
[session 初始化] 解析并冻结 SessionModelCapabilities（§3）
   │   优先级：显式配置 > backend 声明 > Unsupported（fail-closed）
   │   原子写入 model-capabilities.json（先于任何 conversation/prefix 写入）
   ▼
[恢复/启动] 校验当前启动模型与持久化快照兼容（§3.3，兼容谓词）
   ▼
agent: Read("src/screens/shot.png")
   │
   ▼
[工具层] 路径解析 → 能力门 → 有界读（magic 16B 预检 + 头部尺寸探测，§4）
   │   ├─ MIME 双层校验失败 / 头部/尺寸无法解析 → 拒绝（UNSUPPORTED_IMAGE_MIME / INVALID_IMAGE）
   │   ├─ magic 未命中 → seek(0) → 现有文本路径（零变化）
   │   └─ 命中 → 原始字节 SHA-256 → runner commit 落盘（§7.3；无累计准入）
   │        ├─ commit 落盘 home 缓存（不可变对象，§5）
   │        └─ 文本摘要（display path + 尺寸/格式/字节）
   ▼
[持久化层] add_tool_results 追加 tool_attachment（预算元数据 + image://id）
   user content: [tool_result(文本摘要), text(标签), tool_attachment(image://id)]
   ▼
[传输层] convert_messages_to_openai 拆分：
   ├─ tool_result → tool 消息（现有逻辑）
   └─ text/tool_attachment → 残余 user 消息（保持交错顺序）
   │
   ▼
[请求层]
   ├─ 核心投影（stream_backend，router 前）：token 检查 + 读缓存原始字节 + 直接 base64 物化 data URL
   ├─ backend 内：构造最终 body 后精确字节检查
   ├─ 摘要请求：§10.3 已文本化，投影 no-op
   └─ 防御性降级：§15（仅历史 tool_attachment，不改变 Read 协议）
```

核心决策：**`tool_attachment` block 只存 `image://<sha256>` opaque 引用（含预算元数据）；图片原始字节以不可变对象存 `<home>/.mink/cache/images/`；请求时直接 base64 原始字节（无转换、无 variant 缓存）**。

## 3. Session-scoped ModelCapabilities

### 3.1 类型、指纹与统一解析

```rust
pub struct SessionModelCapabilities {
    pub version: u32,                    // 快照格式版本（一期 = 1）
    pub initial_model: String,           // 信息性；指纹不含模型名
    pub image_input: ImageInputCapability,
    pub capability_fingerprint: String,
}

pub enum ImageInputCapability {
    Unsupported,
    OpenAiChatImageUrl {
        detail: ImageDetail,              // low | high（估算档位）
        wire_protocol: WireProtocol,      // OpenAiChatImageUrl（预留扩展）
        token_estimator: TokenEstimator,  // 估算策略标识（§14）
        allowed_mime: Vec<ImageFormat>,   // 模型允许的输出 MIME（双层校验，§4.3）
        max_images_per_request: usize,    // 默认 600（图片数量预算，与 dsh DeepSeek 路由一致）
        max_image_bytes_per_request: u64, // 默认 16MB（原始图片字节累计配额）
        max_image_bytes: u64,             // 默认 16MB（单图原始字节上限，与每请求配额一致）
        max_dimension: u32,               // 默认 16_384（单边上限，头部尺寸）
        max_pixels: u64,                  // 默认 16_000_000（总像素上限，checked_mul）
    },
}
```

- **统一解析函数（唯一入口）**：`resolve_model_capabilities(model, config, backend)`——session 初始化、恢复兼容检查、`/model` 切换三处调用；
- `LlmBackend` trait 增加带默认实现的能力查询（custom backend 零修改）：

```rust
fn image_input_capability(&self, model: &str) -> ImageInputCapability {
    let _ = model;
    ImageInputCapability::Unsupported   // 缺省 fail-closed
}
```

- 优先级（唯一规则）：显式配置 > backend 声明 > `Unsupported`；
- **指纹内容**：`sha256(wire_protocol + detail + token_estimator + allowed_mime + 全部数值限额)`——覆盖所有影响兼容性的字段，**不含模型名**。

### 3.2 创建、崩溃边界与恢复

- 持久化：`<session_dir>/model-capabilities.json`（同目录临时文件 + rename 原子写入，复用 `atomic_file`）；创建后不可变；
- **提交时机**：先于 ① Prefab/PostInitHook 写 conversation、② 第一次 `PrefixManager::ensure()`、③ 第一次 `prefix_snapshot` 事件、④ 第一条用户消息；
- **崩溃边界判定**（无快照时）：

```
无 model-capabilities.json
├─ conversation 无有效消息 且 无 prefix_snapshot 事件
│    → 未完成初始化：重新解析并创建快照
└─ 已有消息 或 已有 prefix_snapshot
     → legacy session：冻结 Unsupported（fail-closed）
```

- 恢复时：重算 fingerprint 并核对持久化字段（不直接信任文件内容）；
- 旧 session 无快照 → `Unsupported`。

### 3.3 启动模型校验与切换（兼容谓词）

- 恢复/启动时（首次 prefix/请求前）：当前配置模型能力与持久化快照比对，不兼容**拒绝启动 turn**；
- 兼容谓词：

```
session.image_input == Unsupported
    → 任何模型均可运行（旧 session 恢复不被拒绝），但 session 永远保持 text-only
session.image_input == OpenAiChatImageUrl(...)
    → MVP：candidate.capability_fingerprint == session.capability_fingerprint 才允许
```

- `handle_model_command` 按同一谓词；不兼容 → 拒绝，保持当前模型与 forced_model 不变，错误含指纹提示新建 session。

### 3.4 静态多模态前缀（能力支持图片时）

第一次构建 prefix（`PrefixManager::ensure` 内）：

1. `tool_surface.schemas()` 后静态增强 Read description（"Read can capture supported raster images (PNG/JPEG/WebP/GIF) and attach them to the next model request. Image capture limits: N images, M bytes per request."）；
2. 增强后的 tools schema **直接进入 ImmutablePrefix**；`capability_fingerprint` 加入 dependency fingerprint（`prefix.rs:54-60`）；
3. `prefix_snapshot` 记录实际 schema；后续请求复用完全相同 tools；压缩后恢复同一版本；无动态 system message。

能力为 `Unsupported` 时（**全关闭**）：

- system prompt 不增加多模态信息；Read schema 完全保持现状；
- **不识别 `image://`**：保持现有未知 resource scheme fail-closed 行为；
- 不做 magic sniff；请求 body 保持现有行为；
- 仅 `Display::render_info()` 提示一次（不写 conversation/system prompt）。

**Prefab 限制（文档化）**：`PrefixSource` 直接返回前缀（prefix.rs:16-21），能力增强不适用；模板作者自行包含能力句；未宣传时功能闲置（低风险）。

### 3.5 fork 继承

**fork 直接复制父能力快照**（`model-capabilities.json` 随会话目录复制，不排除），子代理继承父能力，**不重新解析**。非 fork 子代理（空目录启动）按自身 config 创建新快照。

## 4. 图片识别与头部探测（一期范围）

### 4.1 依赖

```toml
image = { version = "0.25", default-features = false, features = ["png", "jpeg", "gif", "webp"] }
base64 = "0.22"
```

一期只用 image 的**头部探测**（`into_dimensions`，不解码）；完整解码/转换 API 二期复用同一依赖。

### 4.2 识别与探测（不完整解码）

```rust
pub struct ImageInfo {
    pub format: ImageFormat,   // Png | Jpeg | Gif | Webp（封闭枚举，pub(crate)）
    pub mime: &'static str,
    pub width: u32,            // 头部编码尺寸（一期不做 EXIF 转置）
    pub height: u32,
}

pub fn inspect(bytes: &[u8]) -> Option<ImageInfo>;   // magic 16B 预检 + 头部尺寸探测
```

实现（`tools/image.rs`）：

```
1. magic 16 字节预检（快速分派；未命中 → 文本路径）
2. ImageReader::new(Cursor::new(bytes))
   .with_guessed_format()?            // format 探测
   .into_dimensions()?                // 头部尺寸（不解码）
3. 格式 ∈ Mink 支持集合（PNG/JPEG/GIF/WebP）→ ImageInfo；否则 None
```

- **不做**：解码、EXIF 旋转、色深转换、缩放、重编码、palette——全部二期；
- 头部或尺寸无法解析 → `INVALID_IMAGE` 拒绝（fail-closed）；
- **完整性承诺（收窄）**：一期不保证发现深层编码损坏（合法头部 + 损坏正文）；此类错误可能由 provider 在请求时返回（接受，预算上限兜底）。

### 4.3 MIME 双层严格校验（五轮新增）

```
magic sniff 所得 mime
  ├─ ∉ Mink 支持集合（PNG/JPEG/GIF/WebP）→ UNSUPPORTED_IMAGE_MIME（拒绝）
  └─ ∈ Mink 支持集合
       ├─ ∉ 模型 allowed_mime（capability 字段）→ UNSUPPORTED_IMAGE_MIME（拒绝）
       └─ ∈ allowed_mime → 接受，进入捕获流程
```

扩展名不参与判定（与文本路径语义一致）；双层校验任一失败即拒绝，不落盘。

### 4.4 有界读取顺序（保留，含 seek(0) 修正）

```
1. 打开一次文件句柄
2. 读 magic 16 字节
3. 未命中 → seek(0) → 现有文本路径（零变化）
4. 命中 → seek(0) → 同一句柄 take(IMAGE_READ_MAX_BYTES+1) 有界读
5. 同一缓冲区：长度校验 + inspect + digest
```

- 单图原始字节上限：`max_image_bytes = 16MB`（超限报错，不读不存；与每请求 16MB 配额、32MB 最终 body 上限自洽——base64 后单请求图片部分 ≤21.3MB）；
- 单边 ≤ `max_dimension`（16_384）、总像素 `width as u64 * height as u64 <= max_pixels`（16M，**checked_mul**，溢出即拒）；
- 图片路径带行 selector（`:N-M`/`:raw`）→ prepare 前明确拒绝（图片不支持行范围）。

## 5. 图片缓存（home scoped，不可变对象）

### 5.1 布局与作用域（五轮修订：删 index.jsonl 与 request-images/）

```
<home>/.mink/cache/images/v1/
  objects/<sha256 前 2 位>/<sha256>     # 原始字节（content-addressed，不可变）
  tmp/                                   # 两阶段提交暂存
```

- **无 index.jsonl、无 request-images/**：缓存只保存以**原始字节 SHA-256** 命名的不可变对象；
  来源路径**仅写入当前工具结果**（首次 Read 的摘要），**不做跨 session 索引**（五轮删除）；
- 主 agent：`<主 home>/.mink/cache/images/`（跨 session 共享，同图去重）；每个子代理：`<child_home>/.mink/cache/images/`（`child_home = parent_session_dir/subagents/<id>`，sub_executor.rs:126）——**父子不共享对象**；
- **fork 排除**：`copy_session_entries`（sub_executor.rs:334-362）排除 `.mink/cache/`；**`model-capabilities.json` 不排除**（§3.5 继承）；
- 对象 id：`sha256:<hex64>`（原始字节 digest），白名单 `^sha256:[0-9a-f]{64}$`；`image://` 接路径 fail closed。

### 5.2 两阶段提交（保留）

1. `prepare`：校验 + inspect + digest（纯计算，不触存储）；
2. `commit`：`tmp/` 临时文件 `O_CREAT|O_EXCL` + fsync → `link` 到 `objects/xx/<sha256>`（EEXIST 验 digest 去重）→ 两级目录 fsync → 清理。

### 5.3 读回验证

`read_image(id)`：digest 全量校验（+ 可选的头部 probe 元数据核对），失败 → `IMAGE_CORRUPT` → 历史 `[image unavailable]`。

### 5.4 ArtifactManager 零改动；TUI 不复用 ArtifactDisplay

图片**不加入 `ToolExecution.artifacts`**（TUI 会按 `artifact://` 经 ArtifactManager 打开必然失败）。MVP 只显示文本摘要；`AttachmentDisplay`（按 `image://` 渲染）二期。

## 6. `image://` 捕获型协议

### 6.1 语义（能力开启时）

```
Read("src/screens/shot.png")        # 本地路径 → 嗅探分派 → 捕获
  → 摘要: Image: 1024x768 PNG (245.0 KB) — src/screens/shot.png
  → tool_attachment {url: "image://sha256:..."}

Read("image://sha256:...")          # 引用读取 = 真正读图（注入）
  → 命中缓存: 摘要（无路径/文件名——来源路径不持久化，五轮修订）
  → tool_attachment 追加同一 image://id 引用 → 下一请求注入
  → 未命中缓存: 报错（image://<id> not found in image cache）
```

- 幂等：同 id 重复读取重复注入（无害，模型自控频率）；
- **捕获型 scheme，不经过 ResourceRouter**：`Read` 工具解析 path 时特判 `image://` 前缀 → 走图片引用读取路径；`ResourceRouter` 纯文本 handler 语义不动；
- **能力不支持时：`image://` 特判完全不启用**——保持现状未知 scheme fail-closed；
- **引用读取的摘要不含路径/文件名**（无 index 可查）；模型需要路径时重新 `Read` 原路径。

### 6.2 路径信息分布（五轮修订：来源路径仅当前工具结果）

| 层 | 内容 |
|---|---|
| `tool_attachment` | `image://<sha256>` + 元数据——**无路径、无文件名** |
| 首次捕获的工具结果摘要 | display path（相对 cwd）+ basename——**仅本次结果，不持久化索引** |
| 缓存 | 纯对象，无任何路径信息 |

**注意**：conversation.jsonl 整体**包含路径**——Read tool call 参数（`file_path`）与文本 Read 一样原样持久化（现状如此）。准确保证：**`tool_attachment` block 不含路径**。

## 7. 工具结果协议（结构化附件 + quota）

### 7.1 新字段

`ToolOutcome`/`ToolExecution` 增加 `image_attachment: Option<ImageAttachment>`：

```rust
pub struct ImageAttachment {
    pub image_id: String,        // "sha256:<hex64>"（原始字节 digest）
    pub format: ImageFormat,     // pub(crate) 封闭枚举
    pub mime: String,
    pub width: u32,              // 头部编码尺寸
    pub height: u32,
    pub bytes: u64,              // 原始图片字节（配额单位）
    pub name: String,            // basename（剥路径；仅进程内/本次摘要，不持久化）
}
```

### 7.2 Read 执行路径

```
能力门：Unsupported → 现有文本路径（image:// 特判不启用）
path 解析：
  ├─ "image://" 前缀 → §6.1 引用读取路径
  └─ 本地路径：
       1. selector/:raw 校验 → 报错（prepare 前拒绝）
       2. 16 字节 magic 预检；未命中 → seek(0) → 文本路径（零变化）
       3. 同一句柄 seek(0) 后 take(IMAGE_READ_MAX_BYTES+1) 有界读
       4. inspect（§4.2）+ MIME 双层校验（§4.3）+ 尺寸/像素上限（checked_mul）
       5. 图片字节/尺寸/像素校验通过后直接 commit 落盘（无累计准入，§7.3）
       6. commit 落盘（失败 → 该次 Read 返回失败型 ToolExecution）
       7. ImageAttachment + 摘要（display path）
       8. 跳过 memo/snapshot/seen-lines（§11）
```

摘要格式：`Image: 1024x768 PNG (245.0 KB) — src/screens/shot.png\n[The image will be attached to the next model request.]`

### 7.3 请求预算：最后防线（历史引用 = 纯文本，仅压缩清理）

**v7 旧设计（已废弃）**：工具层按“活跃投影累计”做 reserve 准入——长任务/跨轮锁死。

**现行语义（单次消费，与文本同构）**：

- **历史引用是纯文本**（`tool_attachment` 约 100-200 字节 JSON 元数据），与文本历史
  同一生命周期：进入历史即保留，**只被上下文压缩裁剪**；
- 工具层**每 `execute_all` 顺序准入**（v7 §7.3）：图片预算从 0 计数并**跨顺序工具
  flush 共享**（Read→Bash→Read 不重置），只在下一个 `execute_all` 重置；
  超限的 Read 返回**普通失败结果**（不发布、不承诺“下个请求附加”）；
  历史永不锁死新读图；
- 图片 prepare/commit **按调用顺序单张执行**（有界内存：不会同时持有全部图片字节，
  避免大图批量 OOM）；**VFS 图片同样延迟读取**（分类只保存路径，
  `prepare_vfs_candidate` 按调用顺序逐张 `read_image`，backend 返回 None 时
  回退普通文本 Read；backend 错误仍然浮出）；
- **VFS selector/resource 语义**：selector 只有在该路径被**确认是图片**时才拒绝（文本
  Read 的 `:N` / `:raw` 正常）；registered resource（artifact://、skill://、rule://、
  session://）与未知 URL-like scheme 永不进入图片分类（保持 resource 路由语义与
  fail-closed）；
- **单次消费**：每次请求投影时（`project_consumed_attachments`），位于**最后一条
  assistant 消息之后**的引用 = 未消费（物化为 data URL）；之前的引用 = 已消费，
  替换为**确定性文字引用**：
  `[Previously attached image: image://sha256:... (1024x768 png). Use Read with this image reference if visual inspection is needed again.]`
  ——像素只发送一次，后续请求只保留文字引用 + LLM 先前的输出；模型需要再看时
  `Read image://...` 重新注入（闭环完整）；
- **顺序判定（无新增持久化状态）**：结果落盘后、请求前崩溃 → 引用仍在最后一条
  assistant 之后 → 重新发送（不丢图）；压缩裁掉 assistant → 存活的引用视为未消费
  （安全方向：至多重复发送一次）；
- 单次请求预算（`max_images_per_request = 600`、`max_image_bytes_per_request = 16MB`）
  只约束**本次未消费批**（物化层防线，v7 §9.5 降级/失败语义；正常永不触达）；
- **前缀缓存**：已消费引用每次投影为相同文本（确定性）；历史不新增/不压缩时 body
  逐字节稳定，与文本完全一致。

**历史投影不含图片字节**：conversation 中图片引用只有 `image://<sha256>` + 预算元数据
（§8.1），base64/data URL 只在请求时对物化集临时展开（§9.3）。

## 9. 传输层：拆分、投影与物化

### 9.1 消息拆分（保留）

`convert_tool_result_messages`：tool_result → tool 消息；text/tool_attachment → 残余 user 消息（保序）；纯 tool_result 数组行为不变。

### 9.2 职责分层（保留）

核心投影（stream_backend，router 前）：引用解析、token 检查、**读缓存原始字节 → 直接 base64 物化 data URL**、失败语义、防御性复核；OpenAiCompatibleBackend：最终 body 精确检查 `REQUEST_BODY_MAX_BYTES`（32MB）；custom backend 自担限制。preflight token 估算只计本次未消费批（已消费引用已在请求投影中变成文字引用，§7.3）。Router 复制 base64 成本接受 + 测试钉住峰值内存。

### 9.3 物化（五轮修订：无转换、无 variant 缓存）

```
image://<sha256> → 读缓存对象原始字节 → digest 核对
  → data:image/<mime>;base64,<base64(原始字节)>
```

- **直接 base64 原始字节**：不做归一化/缩放/重编码——图片以捕获时原样发送，由 provider 处理（16-bit、EXIF、深层损坏等由 provider 兜底，§4.2 承诺收窄）；
- **无 variant cache、无 request-images/**（二期重编码时再引入确定性缓存）；
- 每请求重新物化 data URL（base64 不跨请求缓存；原始字节读取成本低）。

### 9.4 双表示

本期 `{"type":"image_url","image_url":{"url":"data:<mime>;base64,..."}}`；二期 DeepSeek Files API `{type:"file", file_id}`。

### 9.5 失败语义（超预算按降级/失败处理，不改写历史）

- 历史 `tool_attachment` 与文本同构：**错误超出预算时不做请求时省略**；
- 物化失败（超限/缺失/损坏）的历史块 → `[image unavailable: image://<id>]` 文本 + UI 警告按 id 去重；
- 本轮 attachment（`image_id ∈ this_turn_image_ids`，随用户输入 reset）物化失败 → **当前请求失败**（不谎报"已附加"）；
- 子代理：继承的父 `image://` 引用在子缓存缺失 → 统一按历史 unavailable；模型重新 `Read(original_path)` 自行捕获。

## 12. VFS 只读钩子（保留）

trait 默认方法 `read_image(&self, scope, path, max_bytes) -> Result<Option<VfsImage>> { Ok(None) }`（旧实现零修改）；

## 13. 安全与边界（五轮修订）

| 边界 | 值 | 处理 |
|------|----|------|
| 单图原始字节上限 | `max_image_bytes = 16MB` | 有界读取超限报错，不读不存；16–20MB 无死区 |
| 单边上限 | `max_dimension = 16_384` | 头部尺寸校验，超限拒绝 |
| 总像素上限 | `max_pixels = 16M`（checked_mul） | 头部尺寸校验，溢出/超限拒绝 |
| MIME 双层校验 | Mink 支持集合 ∩ 模型 `allowed_mime` | 任一失败 → `UNSUPPORTED_IMAGE_MIME` |
| 头部/尺寸无法解析 | — | `INVALID_IMAGE` 拒绝（fail-closed） |
| 深层编码损坏 | 一期不保证检测 | **provider 请求时返回错误兜底**（预算上限控制） |
| 每请求预算 | 图数 ≤ `max_images_per_request` / 原始字节 ≤ `max_image_bytes_per_request` | 物化层最后防线：压缩感知（§14）+ 超限降级/失败（§9.5）；历史引用永不被请求时省略 |
| base64 膨胀 | ~1.37x | backend 最终 body 精确检查（32MB） |
| 路径 | tool_attachment 无路径/文件名；来源路径仅当前工具结果 | §6.2 |
| `image://` id | `^sha256:[0-9a-f]{64}$` | 接路径/穿越 fail closed |
| 越权路径 | `resolve_tool_path` 现有逻辑 | 不变 |
| Unsupported 会话 | 不识别 image://、不 sniff、schema/body 不变 | §3.4 |

## 14. Token 与请求预算

- 估算：`tool_attachment` 不计字节（引用形式），按持久化 `width/height` + `detail` + `token_estimator`：
  `high: 85 + 170 × tiles`（tiles `checked_mul`）；`low: 85`；无元数据 → 保守上界（`tiles(max_pixels)`）；
- **单次消费**：已消费引用在请求投影中已变为文字引用，preflight 只对未消费批计图片 token（§7.3）；
- `token_estimator` 策略标识参与 fingerprint（§3.1）；
- 检查：token ≤ `request_input_limit`（图片 token 只计未消费批，§7.3/§14）+ body 字节 ≤ 32MB（backend 内精确）+ 图数/原始字节预算（物化防御，§9.5）。

---

## 15. 文本模型消息降级（防御性机制）

session 冻结 + 兼容谓词后，正常会话不会出现"历史图 + 不兼容模型"。防御性降级**只处理已持久化的历史 `tool_attachment`**，**不改变 Read 工具协议**。触发场景：

- 手工导入的 conversation（含 tool_attachment 导入到 Unsupported session）；
- 缓存损坏/缺失（image:// 对象无法读取——§9.5 unavailable 的文本化呈现）；
- 旧版本 session（升级前含 tool_attachment 的异常数据）。

行为：核心投影把历史 `tool_attachment` 替换为文本占位（`[image unavailable: image://<id>]`），tool_result 文本保留；每 id 一次警告。
**不包含**"custom backend 声明与实际行为不一致"（无 provider 错误分类机制，不能自动触发降级）。
